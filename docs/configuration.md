# Configuration

CodeAtlas is deliberately configuration-light. There is no global config file
yet (that is [PLANNED] for `atlas config`); today configuration is environment
variables and the gitignored `.codeatlas/` directory inside each project.

## Environment variables

| Variable | Meaning |
| -------- | ------- |
| `ATLAS_ROOT` | Project root resolved by the Context SDK, CLI, MCP, and the VS Code extension. Defaults to the working directory. |
| `ATLAS_DB` | Absolute path to an on-disk context database, overriding the default `<ATLAS_ROOT>/.codeatlas/context.db`. |
| `ATLAS_MCP_LOG_LEVEL` | MCP server log level (`debug`/`info`/`warn`/`error`, default `info`). Logs go to **stderr** only. |

Precedence for the database path: explicit `dbPath` option → `ATLAS_DB` →
`<ATLAS_ROOT>/.codeatlas/context.db` (where `ATLAS_ROOT` comes from the
`--repo`/`root` option, the `ATLAS_ROOT` env var, or the working directory).

Provider API keys (e.g. `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, ...) come from
the **user's** environment/config — never from repository files, and never
committed. See [SECURITY.md](./SECURITY.md) and [PRIVACY.md](./PRIVACY.md).

## The `.codeatlas/` directory

`<repo>/.codeatlas/` is gitignored and holds all generated state:

| Entry | Contents |
| ----- | -------- |
| `manifest.json` | Project metadata + context versioning (generated by the scanner). |
| `context.db` | SQLite context database (files, symbols, dependencies, modules, summaries, relationships, hashes, metadata). |
| `usage.db` | AI usage & credits store (ADR-009) — separate from the context database. |
| `tools/<name>.json` | Per-tool Agent Toolkit manifests (TOOL_MANIFEST_SCHEMA_VERSION = 1). |

See [CONTEXT_STORAGE.md](./CONTEXT_STORAGE.md).

## Per-command options

Indexing (`init`/`build`/`update`) and `scan` accept `--repo <path>` to override
`ATLAS_ROOT`/cwd, and `--json` for machine-readable output. The MCP server
accepts `--root <path>` (see [MCP.md](./MCP.md)).

## Ignored paths

The scanner applies a built-in, case-insensitive ignore list (`node_modules`,
`.git`, `dist`, `build`, `.next`, `coverage`, `vendor`). It is not yet
user-configurable; that is part of the planned `atlas config` command.

## SDK options

`createContextSDK({ repositoryPath, dbPath, contextDb, searchDb, ... })` resolves
the same way as the CLI (`resolveContextConfig`). See
[CONTEXT_SDK.md](./CONTEXT_SDK.md).
