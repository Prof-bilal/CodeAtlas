# ADR-009: Usage & Credits as a dedicated `@atlas/usage` feature package behind `UsagePort`

Status: Accepted
Date: 2026-08-11

## Context

The orchestration layer (Direction B) spawns external AI CLIs through
`@atlas/agents` and plans/executes them via the SDK orchestrator (ADR-007,
ADR-008). Task 18 requires an **Usage / Credits service**: record what an agent
or provider call consumed (agent, provider, model, task, session, tokens,
requests, latency, cost), aggregate it, and enforce **budgets** (soft targets)
and **limits** (hard caps) before a call runs.

Requirements:

1. **Tri-state provenance — never guess.** Every token / cost / latency / price
   value must be `actual`, `estimated` (documented, labeled heuristic), or
   `unknown` (`value: null`). Aggregation must not turn `unknown` into a fake
   number. Cost is computed at record time from tokens + pricing.
2. **Pricing is quarantined.** No `if (provider === …)` price tables inside
   business logic; prices come through a `PricingSource` interface (a static
   estimated table today, a live adapter later).
3. **Privacy.** Records never contain prompts, API keys, or provider secrets;
   task references are anonymized hashes.
4. **Composable, SDK-reachable.** The CLI imports only `@atlas/sdk`; the service
   must be reachable as `createUsageService(...)`, returning a `UsagePort`
   contract defined in `@atlas/core`.
5. **Separate persistence.** Usage data is *not* context; it belongs in its own
   store (`.codeatlas/usage.db`), not the `@atlas/storage` context database.

## Decision

- Define the contract in `@atlas/core` as **`UsagePort`** plus the data model
  (`MeasuredQuantity` + `QuantitySource`, `TokenUsageRecord`, `CostRecord`,
  `ModelPrice`, `PricingSource`, `Budget`/`BudgetInput`/`BudgetStatus`,
  `UsageLimit`/`LimitInput`, `LimitCheck`, `UsageProjection`, `UsageEventInput`,
  `UsageRecord`, `UsageQuery`, `UsageStatistics`, `LatencyStatistics`,
  `GroupedUsageStatistics`, `UsageScope`).
- Implement it in a new feature package **`@atlas/usage`** (imports only `core`
  + `shared`): `UsageService` (record / get / list / statistics / budgets /
  limits), `UsageStore` + repositories (SQLite via `node:sqlite`, schema +
  migrations), `StaticPricingSource`, `normalizeEvent`, `computeCost` /
  `combineSources` / `aggregateUsage`, `withUsageTracking` / `trackAgentRun`
  collection seams, and opt-in token estimation (`estimateTokens`,
  character→token, `estimated` provenance only when the provider reported no
  real usage).
- Compose it in **`@atlas/sdk`** as `createUsageService({ filePath?, store?,
  pricing? })` returning a wired `UsagePort`; the SDK re-exports the types and
  errors consumers need. `@atlas/sdk` does **not** re-export the usage package's
  `estimateTokens` — the SDK already exports an `estimateTokens` from
  context-integration (ADR-008) with the same name.
- Enforce limits **fail-safe**: `checkLimit(scope, projection)` returns a failed
  `Result` (`UsageLimitExceededError`) when a projected call would exceed a hard
  limit, so the run seam denies by default. Budgets are soft visibility only and
  never block. No configured limit → always allowed; reads are never blocked.
- Surface it in the CLI as **`atlas usage`** (`summary` / `list` / `budgets`,
  bare `atlas usage` = summary; `--json` on each subcommand; `list` supports
  `--provider`). The parent command declares no `--json` — Commander otherwise
  consumes the flag before subcommand dispatch.

## Alternatives

- **Fold usage into `@atlas/agents` or the SDK.** Rejected: usage is a
  cross-cutting concern (provider calls, agent runs, and future consumers all
  produce it) that must not live in the narrow spawn boundary or bloat the
  composition root with persistence logic. As a feature package it follows the
  same inward-only dependency rule as every other implementation.
- **Add usage tables to `@atlas/storage`.** Rejected: the context database is
  a cache of the repository that can be deleted/rebuilt; usage/credits data is
  independent operational data. Mixing them couples unrelated lifecycles and
  violates the context-database ownership rules (rule 4.4).
- **Store only whatever the provider reports.** Rejected: agents don't report
  tokens; without estimation (labeled `estimated`, never silent) usage would be
  permanently `unknown` for CLI runs and budgets would be useless.
- **Single integer "credits" number.** Rejected: hides provenance and makes
  cost estimates indistinguishable from real billing. The tri-state model keeps
  the system honest.

## Consequences

- **Positive:** one owned persistence home for usage (`@atlas/usage`), a typed
  contract in `core`, a single SDK entry (`createUsageService`) for all
  consumers, quarantined pricing behind `PricingSource`, fail-safe limit
  enforcement, honest estimated/unknown rendering, and full test coverage
  without provider credentials or network.
- **Negative:** one more feature package and a second SQLite store (engine
  `node:sqlite` requires `>=22.5.0`, matching `@atlas/storage`); estimation is
  heuristic by definition and must always be labeled; the CLI cannot configure
  budgets/limits interactively yet (only the service API can today).
- **Follow-ups:** interactive `atlas usage` configuration (set budget/limit),
  live provider pricing adapters behind `PricingSource`, and rendering usage in
  the orchestrator's run reports.
