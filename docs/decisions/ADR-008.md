# ADR-008: Context → Agent integration lives inside `@atlas/sdk` as a `context-integration` module

Status: Accepted
Date: 2026-08-11

## Context

Task 16 ("Context → Agent Integration") assembles the **most relevant context for a
user task** into a normalized, budgeted **Context Package** and delivers it to a
live AI CLI session (Claude / Gemini / Codex / OpenCode) through the existing
**Agent Session Manager**. The integration layer must:

1. read indexed context through the **Context SDK** (`createContextSDK`) — never
   the SQLite database, `@atlas/search`, `@atlas/storage`, or `@atlas/summary`;
2. deliver packages through the **SessionPort** (`createSessionManager()`),
   reusing `SessionLaunchRequest.prompt/args/env` (already reserved by Task 15);
3. be reachable from consumers (the CLI) that may import **only** `@atlas/sdk`
   (plus `@atlas/mcp`) — enforced by ESLint `no-restricted-imports`;
4. keep provider-specific context-injection out of the integration layer (no
   `if (provider === …)` switches) — provider layout stays in `@atlas/agents`
   adapters;
5. preserve the `@atlas/context` deterministic ranker (ADR-001) — selection here
   is deterministic (ranked search + `getRelevantContext`), routing through
   `@atlas/search`'s `RelevanceScorer` seam so a future vector scorer needs no
   caller change.

`@atlas/agents` is a **feature package** (imports only `core` + `shared`); it
cannot depend on the package model (which would create an `sdk → agents → sdk`
cycle). The SDK is the only package that already owns both dependencies the
integration needs: the context façade and the session manager.

## Decision

- Build the integration layer **inside `@atlas/sdk`** under
  `packages/sdk/src/context-integration/`, exported as `createContextIntegration()`
  alongside `createContextSDK` / `createSessionManager`.
- The module assembles a **provider-independent, serializable `ContextPackage`**:
  ranked file/symbol/summary/dependency items + project overview + project
  instructions, each with a score and a human-readable reason; a budget record
  (items / tokens, tail-truncation); a secret **deny-filter** with an exclusion
  record; and an honest **staleness signal**.
- Ranking reuses the scores `@atlas/search` already returns through the SDK
  (`context.search.search`); no scorer is reimplemented. `@atlas/context`'s
  deterministic ranker stays behind its port (ADR-001).
- Delivery goes through the **existing `SessionPort`** (`createSessionManager`):
  `launch()` creates + starts a session with `{ prompt, args, env }`; `attach()`
  supports starting a `CREATED` session with context and reports a typed
  `ContextAttachUnsupportedError` for live/terminal sessions — the current
  adapters run non-interactively, so context is only injectable at launch.
- Provider-specific argument layout stays in `@atlas/agents` adapters (unchanged);
  the integration layer produces a provider-independent prompt string and zero
  `if (provider === …)` switches.
- Staleness detection reads persisted file hashes through a small new SDK read
  method (`ContextSDK.hashes()`) and compares them against the working tree via
  `@atlas/hashing` (`buildSnapshot` + `compareHashes`), falling back to `"unknown"`
  when the on-disk files cannot be hashed. This is the "via `@atlas/hashing`
  change detection when available" path required by Task 16.

## Alternatives

- **New feature package behind a `ContextIntegrationPort` in `@atlas/core`.**
  Rejected (per the task's own "Alternative" option): the SDK is not large enough
  to justify the split; a new package would either be unreachable from the CLI
  (which imports only `@atlas/sdk`) or force a dependency-matrix expansion with
  no benefit. The SDK already composes both the context façade and the session
  manager, so this is its natural home. The ADR-records rule ("keep the signal
  high") also argues against a new port for what is an application-level
  composition, not a new infrastructure seam.
- **Put package conversion in `@atlas/agents`.**
  Rejected: `agents` may import only `core` + `shared`; the package model lives in
  the SDK, so this would create a dependency cycle (`sdk → agents → sdk`).
- **Reimplement ranking in the integration layer.**
  Rejected: `@atlas/search` already ranks deterministically behind the
  `RelevanceScorer` seam; duplicating it would violate "reuse, do not reinvent"
  and break the future vector-scorer upgrade path.
- **Fold staleness into the existing `ContextSDK.status()`.**
  Rejected for now: `status()` already reports `lastUpdated`; working-tree change
  detection is a consumer concern (the integration layer) and adding it to the
  read façade would broaden the SDK for no caller benefit. `hashes()` is a small,
  additive read seam instead.

## Consequences

- **Positive:** one composition point in the SDK; consumers (CLI, MCP, editors)
  reach context-integration exactly like the rest of the SDK; the dependency
  matrix is unchanged (the SDK already depends on `@atlas/agents` and
  `@atlas/hashing`); provider switches are impossible in the layer; `@atlas/context`
  ranker and `@atlas/search` scoring are untouched; the package is serializable and
  explainable end-to-end.
- **Negative:** `@atlas/sdk` gains more application logic (mirroring ADR-005's
  already-accepted trade-off); `attach()` cannot inject into *live* non-interactive
  sessions today (honestly reported as a typed error, per the current adapters);
  staleness is best-effort — it depends on persisted hash keys resolving to real
  files (falls back to `"unknown"` otherwise).
- **Follow-ups:** Task 26 implements `atlas context` build/explain/launch/attach
  CLI commands against this façade. The future `/context` slash-command router
  remains separate; the exported render helpers support that later surface.
