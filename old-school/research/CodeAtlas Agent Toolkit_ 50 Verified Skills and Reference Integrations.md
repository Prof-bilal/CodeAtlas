# CodeAtlas Agent Toolkit: 50 Verified Skills and Reference Integrations

> **Scope note:** The 50 entries below are selected from the verified Agent Skills inventory generated by the internet-skill-finder workflow. They are skills/playbooks or curated skill entries, not all standalone MCP servers. The report separately calls out standalone reference projects such as Headroom, Claude-Mem, and Ponytail.

## Executive recommendation

Do not import all 50 into the runtime at once. Treat the catalog as a governed capability registry. Start with a small default bundle for CodeAtlas: **mcp-builder**, **systematic-debugging**, **verification-before-completion**, **Trail of Bits Security Skills**, **deep-research**, **webapp-testing**, **writing-plans**, **executing-plans**, **using-git-worktrees**, and **react-best-practices**. Add the remaining skills through task-scoped activation so the model does not pay a permanent context cost.

## Important catalog caveats

- Several entries come from aggregator repositories such as `awesome-claude-skills`; the source repository and the actual skill repository can differ. Review the linked target before importing.
- The deterministic selection is balanced for breadth, not a claim that rank 1 is universally better than rank 20.
- The current selected pool contains duplicates or near-duplicates, notably multiple `mcp-builder`, `slack-gif-creator`, and `claude-scientific-skills` entries from different aggregators. Deduplicate by canonical target before runtime registration.
- Token/context tools were underrepresented in the verified Agent Skills inventory. Add the standalone reference integrations below rather than mislabeling them as skills.

## Integration policy for the Agent Toolkit

Every skill should be represented as a registry record with a canonical source URL, version or commit pin, license, capabilities, required tools, risk level, context budget, expected outputs, and verification hooks. Skills should be activated per task packet rather than injected globally. A tool that can write files, execute shell commands, access secrets, or reach the network must pass through the same Capability Firewall used by the Harness.

The runtime should also record whether a skill was merely suggested, loaded into context, invoked, or actually caused a tool call. This distinction matters for cost accounting, auditability, and debugging. Finally, import should be reversible: CodeAtlas must be able to remove a skill cleanly without leaving hooks, MCP registrations, environment variables, or stale memory behind.
